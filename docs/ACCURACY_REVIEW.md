# 정확도 기준 경로 검토 (2026-10-30)

`docs/ACCURACY.md`(자동 생성)의 의심 경로를 그래프·엔진 기준으로 추적한 결과. 지도 앱 실측값은 아직 없다 — 아래는 **엔진 내부 검증**이며 정확도 판정이 아니다.

## 시간 계산 정책 점검
| 항목 | 확인 결과 |
|---|---|
| 역간 시간 출처 | 서울교통공사 OA-12034(출발→도착, 초) + 국토교통부 TAGO 평일 시간표(출발→출발, 07~22시 중앙값). 시간표 쪽은 다음 역 정차(약 30초) 포함(D-040) |
| 환승 시간 | 환승 간선 1개 = 보행시간(15044419) + 대기 180초. **환승 1회마다 정확히 1번** 더해진다(환승 간선에만 있음). 데이터 없으면 300초(추정 플래그) |
| 출발·도착 도보 | 넣지 않는다. 출발역의 모든 노선 노드가 0초에서 시작(멀티 소스, 회귀 테스트) |
| 추정 구간 | 간선마다 `estimated` 플래그 유지 → 표의 `*` |
| 지원 안 함 | 급행·직통열차(9호선 급행, 공항철도 직통, 1호선·경의중앙 급행), 휴일·시간대 차이 |

## 정확도 스크립트 규칙 (`data-build/src/accuracy.ts`)
- 판정은 `입력 대기` / `통과` / `미통과`만. **20개 모두 올바르게 입력돼야** 통과·미통과를 낸다.
- 입력 검증: 둘 다 빈칸 = 미입력, 한 칸만·숫자 아님·0 이하·300분 초과·환승 정수 아님·6회 초과 = 입력 오류(행 번호와 이유 표시, 계산 제외).
- 오차 = |엔진 − 지도 앱|. MAE·표본 수, 추정 구간 없는 경로만의 MAE, 환승 횟수 불일치 수를 함께 출력.
- 사용자 입력은 다시 실행해도 보존(정렬 표기 `---:` 표도 읽음). 다른 자료의 후보값을 자동으로 넣지 않는다.
- 회귀 테스트: 20개 경로 도달, 엔진 ≤ 같은 노선 직통, 다중 노선 출발역 0초 시작, 지선·순환(성수·신정·마천지선, 2호선 순환, 9호선 전 구간, 1호선 연천~신창) 연결.

## 남은 것
- **지도 앱 실측 20개 입력** → `npm run data:accuracy` → 판정.
- 급행 반영(9호선·공항철도·1호선·경의중앙): 시간표에서 일부 역을 건너뛰는 열차를 찾아 급행 구간을 별도 간선으로 넣는 방법을 검토(Phase 6). 정확도 표에서 9호선·공항철도 경로 오차가 크면 우선 착수.
